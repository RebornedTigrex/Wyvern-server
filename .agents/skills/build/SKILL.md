# C++ Build
Контекст задачи: $ARGUMENTS

## Инструкции
1. Если параметры неправильные, но они похожи, на то, что может быть - уточни у пользователя и получи его согласие или правку.
2. Если параметры неполные или их нет, используй значения по умолчанию и собери проект без согласования.
3. Используй `build.ps1` из корня репозитория как основной путь сборки.
4. Не используй прямые вызовы `cmake` вместо скрипта, если пользователь явно не попросил об этом.
5. После запуска кратко отчитывайся по формату из раздела "Формат результата".

## Значения по умолчанию
Если пользователь не указал параметры:
- preset: `x64-debug`
- target: использовать цель по умолчанию из `build.ps1` или из текущего CMakePreset
- build mode: обычная configure + build
- clean: включен
- run: выключен
- jobs: использовать значение скрипта по умолчанию (или явно указанный пользователем `-Jobs`)

## Каноничные команды
Запускай команды из корня репозитория.

Базовая сборка:
`pwsh -File .\build.ps1`

Сборка с preset:
`pwsh -File .\build.ps1 -Preset x64-release`

Сборка конкретной цели:
`pwsh -File .\build.ps1 -Target my_app_target`

Только configure:
`pwsh -File .\build.ps1 -ConfigureOnly`

Только build:
`pwsh -File .\build.ps1 -BuildOnly`

Очистка + сборка:
`pwsh -File .\build.ps1 -Clean`

Сборка и запуск:
`pwsh -File .\build.ps1 -Run`

Параллелизм:
`pwsh -File .\build.ps1 -Jobs 8`

## Диагностика типовых проблем
Плохая кодировка в консоли:
- сначала попробуй `chcp 1251`
- если вывод всё ещё сломан, попробуй `chcp 65001`

Ошибка `vswhere.exe not found`:
- проверь наличие Visual Studio Installer компонентов;
- добавь `vswhere.exe` в `PATH` или установи стандартные VS Build Tools.

Ошибка про отсутствие C++ toolchain в Visual Studio:
- установи компонент `Microsoft.VisualStudio.Component.VC.Tools.x86.x64`;
- повтори запуск сборки.

Ошибка `VCPKG_ROOT is not set`:
- задай переменную окружения `VCPKG_ROOT` на директорию vcpkg;
- повтори запуск.

Ошибка поиска внешних зависимостей CMake:
- проверь пути, переданные в CMake cache/presets;
- если зависимость внешняя, задай нужную переменную пути через параметры скрипта или окружение;
- повтори конфигурацию через `build.ps1`.

Ошибка запуска после `-Run` (бинарник не найден):
- проверь корректность `-Target`;
- убедись, что сборка прошла успешно и артефакт создан.

## Формат результата
После выполнения возвращай:
1. Команду, которую запускал.
2. Ключевые параметры (preset, target, mode, clean/run/jobs).
3. Статус (успех/ошибка).
4. При ошибке: короткая причина и следующий рекомендуемый шаг.
5. При успехе: что именно собрано и был ли запуск бинарника.
